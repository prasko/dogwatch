# Roadmap

Status: Current as of 2026-11-13. Update this page as items land or priorities change.

The design lives in [the coordinated agent workflow](2026-11-11-coordinated-agent-workflow.md) and
[model selection](2026-11-13-model-selection.md). This page tracks what is next.

## Current state

- Eight roles (Lead, Scoper, Architect, Developer, Tester, Validator, Reviewer, Researcher) deploy
  to Codex and Claude Code from shared instructions plus per-tool notes.
- Model tiers (`fast`, `standard`, `deep`, `special`) give each role a default model and effort;
  Lead overrides per assignment. Codex subagent files leave the model to the spawning call.
- Reviews are flattened for background stage owners; scope review is optional and Lead's call for
  large tasks. Each tool reviews with its own Reviewer.
- A Codex review of the Codex side passed. Nothing is deployed yet.

## Before further work: deploy and verify

1. Deploy: `python3 scripts/deploy.py --dry-run`, then `python3 scripts/deploy.py`. This backs up
   and replaces the existing Codex files and adds the Researcher and Claude agents.
2. Claude: `/agents` lists the eight `agentic-*` agents with the intended model and effort, and
   accepts the `effort` and `tools` frontmatter keys (`Grep` and `Glob` names included).
3. Claude: `claude --agent agentic-lead` applies the agent's model and role prompt to the main
   session, and CLAUDE.md still loads.
4. Codex: `/status` in `codex --profile agentic-lead` shows the profile's model and effort; a
   spawned subagent runs on the passed model.
5. Herdr: Lead launches an interactive specialist for each tool with `-- --agent ...` or
   `-- --profile ...`, and replies arrive through `herdr agent prompt`.
6. Run one small task end to end in each tool, including a flattened review.

## Priorities

### 1. Roles as skills for small tasks

Goal: small tasks avoid the overhead of starting subagents. Some role procedures become skills that
the current agent loads and runs in its own context, for example scoping or a concise plan in Lead,
or a review checklist.

Open questions:

- Which roles to offer as skills, and whether the skill and agent versions share one source.
- How Lead chooses between running a skill itself and delegating to a fresh context. Independent
  review probably stays a separate context.
- Packaging and deployment for both tools: Claude `~/.claude/skills/`, Codex `~/.agents/skills/`.

### 2. Cross-provider review

Goal: the Reviewer runs on the other tool to bring a different model's view. Deferred from the first
Claude rollout to keep headless review simple.

Open questions:

- Headless (`claude -p`, `codex exec`) versus a Herdr pane. A pane is visible, while the work it
  reviews may be a background subagent, which is inconsistent. Headless runs inside the caller's
  sandbox and needs network access to the other provider and write access to its config home.
- Model and effort for the other tool's Reviewer; reuse the tier map.
- Optional input to implementation reviews: Claude `/code-review` or Codex `/review`. Both cover
  code only, and higher Claude levels start their own subagents.

### 3. Per-repository secretary

A plain session per repository that starts and keeps track of Leads. Not a role yet; try it by hand
first and record what it repeatedly does.

### Later

- Research and task-splitting skills, and cross-worktree orchestration
  ([workflow design](2026-11-11-coordinated-agent-workflow.md)).
- Codex compaction settings and model context sizes.

## Context and compaction (Claude)

All current Claude models have a 1M context window. Claude Code compacts at `autoCompactWindow`
(settings, per model or top level, 100k to 1M or `"auto"`), overridden per session by
`CLAUDE_CODE_AUTO_COMPACT_WINDOW`. `"auto"` is chosen remotely per model.

- Decided: Lead always runs with a 1M window:
  `CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000 claude --agent agentic-lead`.
- On hold: a per-role window for interactive Scoper, Architect and Developer, applied with
  `herdr tab create --env CLAUDE_CODE_AUTO_COMPACT_WINDOW=<n>`. Revisit if they hit compaction.
- Open: whether the global default should be `"auto"` or an explicit window; check `/autocompact`.
